# Markdown guidelines

- Follow CommonMark; preserve required platform-specific syntax.
- Use plain language, consistent terminology, and explicit references. Avoid vague pronouns when their meaning could be ambiguous.
- State each rule once. Keep its conditions and exceptions together; distinguish requirements from preferences.
- Use descriptive ATX headings (`#`) with consistent hierarchy. Separate blocks with blank lines.
- Prefer short paragraphs and flat bullet lists. Use numbered lists when order matters.
- Prefer lists over tables. Use tables only when row-column relationships materially improve clarity.
- Avoid charts, diagrams, and ASCII art unless requested or substantially clearer than text. Keep essential instructions available as text.
- Use inline code for commands, paths, identifiers, and literal values.
- Use fenced code blocks with language identifiers. Include examples only when they clarify otherwise ambiguous behavior.
- Use descriptive links. Keep essential rules in the document rather than only in linked references.
- Avoid decorative symbols, redundant emphasis, raw HTML, unnecessary escaping, and HTML whitespace entities.
- Preserve frontmatter, directives, code, and technical meaning. Avoid unrelated reformatting.
- Check heading hierarchy, edited links, and code fence balance.
